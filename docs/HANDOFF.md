# PixelReel 交接说明

## 当前能力

- 电影、剧集、游戏统一资料库及记录详情
- 豆瓣、Trakt、Steam、Xbox、PSN 导入与审核
- Microsoft Xbox OAuth 直连及 OpenXBL 兼容来源
- `GamePlatformEntry` 分平台保存游玩时间、成就和奖杯
- 时间线、首页行动队列、Showcase、年度分析和雷达
- 数据健康审计、重复候选、人工合并预览与安全撤销
- 活动日志、后台任务、同步历史与双语界面
- `pixelreel-library-export` v2 校验快照、只读恢复预览和二次确认的增量安全恢复

项目面向单用户自托管。多用户注册、租户隔离、公开个人主页和覆盖式或选择性快照恢复均不在当前
实现范围内。

## 必须保持的产品语义

- 豆瓣影视和原始字段不可删除或改写。
- 外部导入的新记录进入 `PENDING`，忽略不等于删除。
- 标题只能提示重复候选，不能自动绑定、合并或删除。
- 平台指标以 `GamePlatformEntry` 为准；零时长不等于未知。
- PSN 使用“奖杯”，其他平台使用“成就”；未知总数不生成比例。
- 前端异步读取采用最新请求获胜，刷新失败不能清空已有数据。
- 同一外部服务请求至少间隔 2 秒。
- 恢复预览只读；增量恢复经二次确认只创建快照独有数据，内容不同不覆盖、现库独有不删除，
  身份冲突或现库指纹变化必须中止。

## 接手顺序

1. 阅读根目录 `AGENTS.md` 和 [架构文档](ARCHITECTURE.md)。
2. 按 [运行手册](RUNBOOK.md) 启动并运行后端、前端检查。
3. 通过 `/api/health` 确认数据库，记录数量只作为当前运行快照读取。
4. 涉及平台同步时阅读 [接入指南](INTEGRATIONS.md)，先只读验证再正式同步。
5. 涉及数据库写入时先确认豆瓣保护、导入审核和重复合并边界。

## 后续方向

对个人使用，后续重点是处理导入审核和重复候选、改善移动端细节，并在增量安全恢复基础上
另行设计选择性修复；选择性修复仍不能覆盖豆瓣原始字段或删除受保护记录。若扩展为多人产品，需要重新
设计用户归属、会话、权限和数据隔离，不能直接在当前全局资料库上增加注册入口。

历史计划和已完成阶段记录只用于追溯，不应直接作为实现任务；文档边界见
[docs/README.md](README.md)。
